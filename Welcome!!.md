#### Using tags in building association
#tags are a feature which has a variety of behavior, but in its essence creates an association between notes as well as being an object that you can search for and manipulate[^1]

- **To search for tags**, navigate to the magnifying glass icon in the top left. Try typing out **tag:#plant** to search for all of the files that are relating to plants. The output should look something like this: 
  ![600](https://i.gyazo.com/6ec8891dfa54d34ed2e711072ae94479.png)

	This output gives where the tag is found, allowing you to jump to this tags location in the Anise, Tag List, Calendula, or the 37 other files in which this tag occurs.

- **Tags can also be visualized.** Open a new tab and then press ==ctrl+g==... 
		*BOOM! Graph view :)* 
	![600](https://i.gyazo.com/ef7e5b0aa6de950b469ff5a6ed0fe8e7.png)

If it looks overwhelming, that is because it is! This is all the information that the vault contains including the connections that are being made. The current use case is to see the emerging connectivity being formed from the tag system as well as [[Welcome!!#Using links|wikilinks]], but there are ways to make it more focused on certain groups of files. [^2] Here are some notable features about this tool: 
	1. All the various dots in the gradient cold blue to hot yellow gradient, connected directly to the black, 10-pointed star are #tags. They relate to a particular concept surrounding gardening, medicine, or the environment. You can search for the tags using the gear icon in the top right of the graph view.
	2. Connections are updated in real time! Simply change a global property of a file and it will be instantly displayed on the graph. 
	3. The properties of each node can be seen by hovering over them allowing for a quick overview of the semantic associations with each note in the graph. 
	4. Forces and distances of connections can be modified along with other properties to change the size, shape, and emergent structure of the graph. Each node can be grabbed and separated as well to facilitate this. 
**As a tool, the graph view serves as the most direct and informationally dense overview of all information in the vault. Its extended version provides more visual fidelity in discerning each node from one another (i.e. shapes, colors, animated lines, and tag filtering.)**

#### Using links
As you saw in the graph view, there are many other links between files that exist that are not directly mediated by a tag. All of these lines are because of [[links]]. Some links [[aren't highlighted]], meaning that they are pointing to no file. Links that do point to a file are bright, such as [[~Tag List]], [[01Action plans]], [[Anise]], and so on. Creating a link is easy! simply use two square brackets and sandwich your text in-between them, like so \[\[ \]\] (without the slashes).  Alternatively, right click and select "**add link**" to create these square brackets around whatever you highlight.

Example of what you should see when typing into the double square brackets:
![700](https://i.gyazo.com/54b3ca9ab4c4364a101094f5bc2f497d.png)

After that, simply type in the name of the file that you want to link to and *voila*! Now you have connected to notes together! The next challenge is to do so with meaning and intention. If practiced, this tool can make a map that can look semantically similar to the territory that we are trying to explore,. Each wikilink adds another layer of complexity and connectedness to notes and increases the continuity between pieces of disparate information. They are a powerful form of connection to create a collection of notes with an emergent message, idea, plan, or subjectivity.

Some other behaviors to note about greyed out links. These files can be instantiated later, which can be more useful than one would expect when thinking about longer term learning projects. Don't be afraid to add empty links to remind yourself that you want to create that site. **Empty links can also pop up in the graph view.**

For more on links, visit the [obsidian help site](https://help.obsidian.md/links).

#### Using the search bar syntax
There are certain prefixes to searches that can help parse down your criteria for what you are searching for. Without these, the search functionality is a complete mess, so before you type the keyword you want to search discern whether it is a file, tag, inline text, path, or property, or section that you are referring to

- **file:{your_TEXT_here}** --> "Search for a file name that contains or matches {your_TEXT_here}"
- **line:{your_TEXT_here}** --> "Search for a line in a file that contains or matches/containes {your_TEXT_here}"
- **tag:{your_TEXT_here}** --> "Search for a tag in the vault that contains or matches {your_TEXT_here}"
I rarely use the ones below
- **path:{your_TEXT_here}** --> "Search for a path name that contains or matches {your_TEXT_here}"
- **\[{your_TEXT_here}]** --> "Search for a property which contains or matches {your_TEXT_here}"
- **section:{your_TEXT_here}** --> "Search for a section (header) that contains or matches {your_TEXT_here}"

file:  and tag: are the main prefixes that I use, so they inform the organization of this vault in its current state the most. 

Use ctrl + shift + f to search instantaneously, or use the search bar located in the top left.

#### Using the command pallete
I cannot tell you how many times that I've pressed ctrl+p in this vault. It is the most useful hotkey you have since it can be used to access EVERY command/action that is in the base version of osbidian or installed through a community plugin. Give it a shot! 

What you should see upon pressing ctrl+p: 
![](https://i.gyazo.com/46e5480d72ab64648fb9024acefe4a9a.png)

#### List of useful commands
- "Insert template" -> within the current focused file, insert a template that is defined from another file. All template files are located in the "~Templates" folder and can be modified. Any new templates added to the folder will be added to the list of available templates
- "Workspaces: Manage Workspace Layouts" -> Save, delete, and switch between workspace layouts. These layouts are meant to provide a way to quickly switch between specific tasks and workflows in the vault with a click of a button. Instead of either having to commit to the last task that is set up in the obsidian UI or having to compromise with a setup that is subpar, simply open the workspaces layout, switch to a workspace corresponding to your task, and now you have instant access to a UI accomodating *that specific task*. New workspaces for new purposes can be made on the fly, making sessions re-accessible at a later date. 
- "Excalidraw: Create new Drawing" -> Excalidraw is a plugin that allows you to create your own drawings, image boards, and diagrams to create visually engaging notes, presentations, and more. It supports importing of your own custom images, can convert code into diagrams, and more.
- "Daily notes: open today's daily note" -> If you are a fan of logging daily progress or just simply documenting information into one file for later processing, this is the perfect tool for you. 

The command pallete gives you access to all the plugins, settings, and base commands through a simple search bar. It's utility hinges on your imagination.

#### Properties
If you navigate to the templates folder, you will notice that the templates have these blocks at the very top of them containing a key (on the left) and a value (on the right). [[Action template|Simply click here for an example.]]

![800](https://i.gyazo.com/d1d8835d915b222246504cb9fd5c10bd.png)
These properties, at least for this specific template, are not so intimidating and don't need to be finagled with. The year, month_start, and month_day properties take on a value when the insert template function is used. Furthermore, the UsageNum and LastDateMod properties or for the engagement tracker immediately below the property list[^3]. Overall, the properties on this file are more for tracking dates and maybe writing in a blurb under the Specific_usage property.

For action notes, properties are trivial in their relevance.
However, plant notes have...

![800](https://i.gyazo.com/e70f058a09d7bf112e7a62ed3324c4ae.png)
... many properties! Their properties are tied into a base file which sorts each according to their various properties. In this way, from a higher view, we can organize plant notes on the scale of dozens or hundreds of notes using simple shared properties. This implementation of properties can be seen in the [[Plant YAML tables.base]] file. 

**If you are going to commit to contributing to plant entries, it is required to either document your non-compliance with filling out these properties, so that they can be filled out later, or to learn how to identify each property and associate it with new research.** I'd highly recommend  the usage of these properties when you are creating your own plant entries as it ties new entries in with the existing organizing structure thus allowing for a relations between plants, and their benefactors, to be readily perceived and utilized. The connections between which plants will work well together depending on functional properties, priortizing human use cases, and ensuring that the layers of plants are not going to lead to too competitive of a garden for certain plantlings, will emerge *easier* if you use and fill out the plant note template properties as you study. With enough plants documented in this way, the number of garden designs are limitless and functionally achievable with the proper combinations of plants.
